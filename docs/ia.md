## 1. 사이트맵

### 1-1. 전체 트리

```
sp-project-portal
│
├─ 인증 영역 (비로그인 접근 허용)
│   ├─ 로그인 [공통, redirect 파라미터 지원]         (SCR-AUT-001)

├─ 글로벌 영역 (로그인 후)
│   ├─ 프로젝트 목록 [공통, 역할별 필터]              (SCR-GLB-001)
│   ├─ 프로젝트 생성 [팀]                            (SCR-PRJ-002)
│   ├─ 계정 설정 [공통]                              (SCR-ACC-001)
│   └─ 관리자 메뉴 [관리]
│       ├─ 프로젝트팀 계정 관리                      (SCR-ADM-001)
│       │   └─ 계정 생성·수정 폼                     (SCR-ADM-002)
│       ├─ 고객사 계정 관리                          (SCR-ADM-003)
│       │   └─ 계정 생성·수정 폼                     (SCR-ADM-004)

    ├─ 대시보드 [공통, 영역별 가시성 §1-1 참조]       (SCR-PRJ-001)

    │   ├─ TC 상세 [팀(QA)]                         (SCR-TST-002)
```

## 4. 진입 동선

### 4-1. 두 가지 로그인 진입 경로 (REQ-AUT-007)

```
[A. 일반 로그인 URL: /login]
    │
    ├─ 관리자 로그인       ──▶ SCR-GLB-001 (전체 프로젝트 목록)
    │                              │
    │                              ├─▶ 관리자 메뉴 (SCR-ADM-001~005)
    │                              └─▶ 프로젝트 선택 ──▶ SCR-PRJ-001
    │
    ├─ 프로젝트팀 로그인    ──▶ SCR-GLB-001 (담당 프로젝트 목록)
    │                              │
    │                              ├─▶ 프로젝트 생성 (SCR-PRJ-002)
    │                              └─▶ 프로젝트 선택 ──▶ SCR-PRJ-001
    │
    └─ 고객사 로그인        ──▶ SCR-GLB-001 (참여 프로젝트 목록)
                                   └─▶ 프로젝트 선택 ──▶ SCR-PRJ-001


[B. 프로젝트별 고유 URL: /projects/{id} 직접 접근]
    │
    ├─ 비로그인 상태       ──▶ /login?redirect=/projects/{id}
    │                              └─▶ 로그인 성공 ──▶ SCR-PRJ-001 (원래 URL 복귀)
    │
    └─ 로그인 상태         ──▶ SCR-PRJ-001 (해당 프로젝트 대시보드 직진)
                                   · 참여 권한 없으면 SCR-SYS-403
```

> 별도의 프로젝트별 로그인 URL은 두지 않음. 단일 `/login` + redirect 파라미터로 처리하는 표준 패턴 채택.

### 4-2. 역할별 주요 작업 동선

**신규 사용자 (초대 수락 첫 진입)**
```
이메일 수신 ──▶ 초대 링크 클릭
            ──▶ SCR-AUT-004 (초대 수락·비밀번호 설정)
            ──▶ 비밀번호 정책 통과
            ──▶ 자동 로그인
            ──▶ SCR-PRJ-001 (참여 프로젝트 대시보드)
```

**관리자**
```
로그인 ──▶ 전체 프로젝트 현황 ──▶ 특정 프로젝트 대시보드
       └─▶ 관리자 메뉴 ──▶ 계정 관리 / 감사 로그
```

**프로젝트팀(PM)**
```
로그인 ──▶ 담당 프로젝트 목록 ──▶ 대시보드
                                     │
                                     ├─▶ 요구사항 파일 업로드/재업로드 (MOD-FILE-001)
                                     ├─▶ 산출물 업로드 (단계별)
                                     ├─▶ [검토 요청] 발송 (MOD-WF-001)
                                     ├─▶ [AI 개발 시작] (MOD-DEV-001, 사전조건 충족 시)
                                     ├─▶ 프로젝트 설정 ──▶ 팀 멤버·고객사 초대 (SCR-SET-002)
                                     │                       └─▶ 초대 재발송 (MOD-AUT-001)
                                     └─▶ 워크플로우 이력 확인
```

**고객사**
```
프로젝트별 URL 접근 ──▶ 로그인 ──▶ 대시보드 (직진)
                                       │
                                       ├─▶ 미처리 항목 카드 확인
                                       ├─▶ 요구사항 파일 검토·코멘트
                                       │       └─▶ 컨펌/반려 (MOD-WF-002)
                                       ├─▶ 산출물 파일 검토·코멘트
                                       │       └─▶ 컨펌/반려 (MOD-WF-002)
                                       └─▶ UAT 결함 등록 (20~21단계)
```

## 5. IA 결정 사항·전제

| 항목 | 결정 | 사유 |
|------|------|------|
| 단일 포털 구조 | 고객사·프로젝트팀·관리자가 **같은 도메인·같은 시스템**을 사용 | 별도 포털 분리는 MVP 과스코프, 가시성·메뉴 제어로 충분 |
| URL 풀폼 통일 | 모든 자원 경로 풀폼(`/projects/{id}`). 축약(`/p/`) 미사용 | REST/URL 디자인 표준: 일관성·약어 회피 |
| 컬렉션 자원 복수, 단일 자원 단수 허용 | `/projects`·`/admin/teams`·`/invitations` 복수. `/account`(본인 자원)·`/login`·`/password` 단수 유지 | REST 컨벤션 + 보편 패턴 (GitHub `/settings` 등) |
